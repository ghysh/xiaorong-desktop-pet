# 自主行为调度规范草案

## 行为集合与候选节奏

自主序列未来包括眨眼、原地待机、停止观察、短距离行走、盘腿睡眠和自主醒来。以下均为 10A 候选，进入运行前需用户确认和模拟测试：

| 行为 | 候选触发/持续 |
|---|---|
| 眨眼 | 待机中每 3～8 秒安排一次 |
| 停止观察 | 自动循环中约 20%～35%，持续 4～12 秒 |
| 短距离行走 | 自动循环中约 10%～20%，持续 1～4 个步态循环或约 2～8 秒 |
| 盘腿睡眠 | 连续低互动 10～30 分钟后才可候选，持续 2～15 分钟 |
| 自主醒来 | 到期、点击、提醒或用户舞蹈请求触发 |

概率不是每帧投掷；`BehaviorController` 的局部随机生成器只在行为边界选下一意图和时长，固定 seed 可复现。每个高层行为必须有最短驻留和最大时长，避免快速横跳或无限走动。

## 优先级与打断

```text
拖拽 > 用户舞蹈 > 提醒 > 起身/坐下 > 自主行走 > 自主睡眠 > 点击 > 眨眼 > 待机
```

退出和暂停位于所有行为之上。关闭“自动行为”后，只保留静态/普通待机与用户输入，不再安排窗口移动或睡眠。拖拽立即终止自动位移；用户舞蹈覆盖并冻结自动计划；提醒在拖拽/舞蹈时排队；睡眠由点击唤醒而不是播放普通点击反馈。

## 与现有 BehaviorController 的关系

现有控制器继续作为唯一高层自动调度器，未来扩展少量高层状态和转换原因。它不保存具体帧、不移动 QWidget、不显示提醒。具体剪辑交给 `ActionPlayer`，位移交给 `WindowMotionController`，提醒到期交给 `ReminderController`。10A 不修改当前状态枚举或转换表。

## 屏幕与体验边界

- 使用 `screen.availableGeometry()`，避开任务栏，支持负坐标副屏。
- 不在显示器间瞬移，不频繁跨屏，不完全移出屏幕。
- 不跟随鼠标，不自动遮挡当前输入区域；未来只能用有限启发式，不采集用户活动数据。
- 每次移动有冷却期；到边缘转身或停止，禁止快速来回横跳。
- 用户关闭自动行为、隐藏、暂停或退出后立即停止未来调度和位移。
- 透明像素仍阻挡下层窗口，需继续作为体验限制提示。

测试必须覆盖固定 seed 序列、上下限、关闭开关、拖拽抢占、负坐标屏幕、边缘、系统睡眠恢复、无第二个高频定时器和无后台线程。
